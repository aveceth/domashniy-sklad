# Домашний продуктовый склад — версия 0.2

Папка готова для редактирования в **Visual Studio Code**. Это PWA для Android, iOS (iPhone/iPad) и компьютера. Установка на телефон возможна после размещения на HTTPS-домене. PWA не требует магазина приложений.

## Локальный запуск в VS Code (Windows)

1. Откройте папку `domashniy-sklad` в VS Code: «Файл → Открыть папку».
2. Откройте «Терминал → Новый терминал» и введите `py -m http.server 8000` (или `python -m http.server 8000`, если команда работает).
3. Перейдите на http://localhost:8000. Чтобы остановить сервер, нажмите Ctrl+C.

Также можно дважды нажать `start-windows.bat`. Если Python не определяется, установите расширение **Live Server** в VS Code, нажмите правой кнопкой по `index.html` и выберите **Open with Live Server**. **Важно:** Live Server использует собственный порт и адрес — это другая отдельная локальная база IndexedDB. Чтобы не терять видимость старых данных, открывайте тот же адрес и порт, что раньше, или переносите данные JSON.

Не запускайте `index.html` напрямую через `file://` — модули и PWA могут не работать.

## Где находятся изменения

| Файл | Назначение |
| --- | --- |
| `app.js` | Карточки, логика, суммы и история покупок по месяцам, облачные кнопки |
| `expiry-rules.js` | Индивидуальные приблизительные сроки по известным видам продуктов и местам хранения |
| `styles.css` | Внешний вид компьютера и телефона |
| `db.js` | Локальная база IndexedDB; структура не изменена с 0.1 |
| `cloud.js` | Регистрация, вход и сохранение/восстановление облачных копий |
| `cloud-config.js` | URL и публичный ключ Supabase — нужно заполнить для облака |
| `supabase.sql` | Создание защищённой таблицы для резервных копий в Supabase |
| `manifest.webmanifest` | Установка PWA на телефон |
| `sw.js` | Офлайн-кэш и обработка поступающих push-сообщений |

### Что сделано в 0.2

- Главная метрика «Покупки за месяц» открывает помесячную историю по нажатию. На первое число сумма нового месяца равна нулю (если в нём ещё нет покупок), история других месяцев не стирается.
- Убрана стоимость остатков из главного экрана, карточек продуктов и страницы расходов.
- Автоматический расчёт опирается на название конкретного продукта и место хранения. Если нет подходящего правила, срок **не назначается**. Справочник в `expiry-rules.js` можно расширять. Даты — ориентиры, не проверенные индивидуальные сроки безопасности. На упакованных товарах ориентируйтесь на этикетку.
- Облачная копия Supabase по единому аккаунту доступна после настройки. **Это ручное сохранение и восстановление, а не живая синхронизация двух одновременно редактируемых устройств.** Функция восстановления заменяет все данные текущего устройства — заранее сохраняйте собственный JSON.
- В `sw.js` подготовлен приём Web Push. **Фоновые уведомления ещё не отправляются:** нужен настроенный push-сервер, VAPID-ключи, подписка каждого телефона и серверный ежедневный планировщик.
- Добавлен `id` PWA-манифеста для более стабильной установки, обновлён офлайн-кэш.

## Как сделать доступным на Android и iPhone

1. Опубликуйте содержимое папки (не ZIP) на статическом HTTPS-хостинге, например GitHub Pages, Netlify или Cloudflare Pages.
2. Откройте HTTPS-ссылку на телефоне. Android: Chrome → меню → «Установить приложение» / «Добавить на главный экран». iPhone: Safari → «Поделиться» → «На экран Домой».
3. Если добавили значок, открывайте приложение через него. На iOS Web Push для веб-приложений на главном экране доступен с iOS 16.4, но его отправитель в этой версии ещё не создан.
4. Данные разных адресов, устройств и браузеров сами по себе **не объединяются**. Используйте облачную копию или JSON.

## Настройка облачной резервной копии (одинаковый аккаунт на разных устройствах)

1. Создайте проект на https://supabase.com и включите Auth → Providers → Email. По умолчанию возможна необходимость подтвердить e-mail при регистрации.
2. В панели Supabase откройте SQL Editor, вставьте содержимое `supabase.sql` и выполните скрипт.
3. В Supabase Project Settings → API скопируйте **Project URL** и **publishable/anon** key в `cloud-config.js` в поля `SUPABASE_URL` и `SUPABASE_ANON_KEY`. **Никогда не вставляйте service_role/secret key** в файлы сайта.
4. Перезапустите страницу / опубликуйте обновлённую версию. На странице «Настройки» зарегистрируйтесь и войдите; на первом устройстве нажмите «Сохранить в облако».
5. На втором устройстве войдите в **тот же аккаунт** и нажмите «Загрузить из облака». Все данные второго устройства будут заменены копией.
6. Прежде чем перейти с устройства А на Б, сначала сделайте новую облачную копию на А; прежде чем вернуться на А — сохраните копию на Б. Параллельные изменения не объединяются. Для полноценной автосинхронизации нужна отдельная модель по записям с разрешением конфликтов.

**Защита:** SQL включает RLS, поэтому пользователь может читать и перезаписывать только собственную резервную копию. Облачная копия включает фото и историю покупок; проверяйте лимиты хранилища своего тарифа Supabase. Облако требует интернет-подключения.

## Push-уведомления — что ещё потребуется

Обработчик `push` и `notificationclick` в `sw.js` подготовлен. Для реально работающих фоновых уведомлений нужна серверная реализация: отправитель Web Push с VAPID, таблица подписок, защищённый API регистрации подписки и ежедневная задача, выбирающая партии с ближайшим сроком. Подписки хранятся отдельно для каждого устройства. Фоновый JavaScript самой страницы не может надёжно запускаться каждый день при закрытом браузере. На iPhone приложение нужно установить на главный экран и отдельно разрешить уведомления.

## Важные замечания

- В старой версии данные хранились в IndexedDB `home-pantry-v1`. Имя базы и хранилища **не менялись**, поэтому при запуске по тому же адресу и порту сохранённые записи останутся.
- Миграция данных не нужна. Рекомендуется перед обновлением экспортировать JSON в настройках старой версии.
- Если после замены файлов остаётся старая страница, закройте вкладки и обновите страницу; сервис-воркер обновит кэш до v2.
- Демо-записи могут создавать расходы текущего месяца; при необходимости удалите демо или сбросьте данные и введите собственные записи.
- Стоимость покупки фиксируется при первоначальном добавлении партии; изменение количества уже купленной партии не корректирует исторический расход.
- Индивидуальные ориентиры не заменяют оценку состояния продукта и срок на этикетке.
- Фото по-прежнему распознаёт только штрихкод в поддерживаемом браузере, не дату и не товар визуально.
