# Домашний продуктовый склад v0.4.1

## Перед заменой

1. В установленном приложении сделайте **Настройки → Скачать JSON**. Сохраните файл в безопасном месте.
2. Распакуйте ZIP, скопируйте его содержимое в **существующую** папку проекта VS Code. Не заменяйте `.git`, не создавайте вложенную папку проекта.
3. **Проверьте `cloud-config.js`**: архив содержит публичную конфигурацию из переданной сборки. Если вы позже меняли адрес Supabase или ключи, сохраните свою актуальную конфигурацию. Приватные ключи там хранить нельзя.
4. Выполните `git add .`, `git commit -m "Версия 0.4.1 — надёжность"`, `git push origin main`.
5. Дождитесь успешного GitHub Actions Pages. Откройте установленное приложение, нажмите **«Обновить»** при появлении баннера. Закройте и снова откройте.
6. Убедитесь, что продукты и покупки сохранились, вход в Supabase работает, подписка на Web Push сохранилась.

## Изменения

- В сортировке запасов, блоке «Ближайшие продукты», срочном списке и статусах используется **ранняя дата диапазона**, если она есть. Без срока продукт показывается в конце.
- Демонстрационные покупки больше не учитываются в истории и месячных расходах. Старые события помечаются как демо **только при надёжном совпадении** с ещё существующей демопартией: одинаковые название/дата/цена и время создания в пределах 15 секунд. Если демопартия давно удалена, событие не распознаётся автоматически — реальные покупки не затрагиваем.
- После ошибки загрузки в облако изменения помечаются как несохранённые и повторно отправляются с ограниченным экспоненциальным интервалом; после перезапуска/возврата сети попытки возобновляются. В настройках показывается состояние облачной копии.
- Изменения списка покупок тоже запускают отправку облачной резервной копии.
- Service Worker сохраняет **кнопочное** обновление (новый worker ждёт подтверждения), а загрузку обычных файлов делает по стратегии «сеть в первую очередь». Старые кеши удаляются только после активации нового worker. Обработчики `push` и `notificationclick` сохранены.
- Исправлен устаревший текст о серверных push в настройках.

## Ограничения

- **Не** создана двусторонняя синхронизация. Основной телефон по-прежнему перезаписывает общий снимок Supabase; не включайте автосохранение на нескольких телефонах.
- Без сервера нельзя гарантировать точную доставку уведомлений к 09:00. Развёрнутая Edge Function и Cron **не изменены**, все настройки сервера и SQL остаются прежними.
- Реальные тесты доставки push на конкретном телефоне и GitHub Pages нужно выполнить после публикации.
- Данные IndexedDB `home-pantry-v1` и структура JSON версии 1 сохранены; никаких миграций схемы или серверных SQL не требуется.
- При редком одновременном ручном и автоматическом сохранении основной телефон остаётся единственным источником истины.

## Самопроверка (при наличии Node.js)

Из корня проекта: `node --test tests/*.test.mjs`. Если установлен Node.js, можно также проверить синтаксис `node --check app.js` и `node --check sw.js`.
