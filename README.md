# Домашний продуктовый склад — версия 0.5

Рефакторинг стабильной версии 0.4.1 **без изменения внешнего вида и структуры данных**.

## Что изменено

- `cloud-sync.js` — управление фоновыми резервными копиями: отметка несохранённых изменений, повтор после сбоя сети, статус и включение/отключение. Логика вынесена из `app.js` и доступна для тестирования.
- `pwa-updates.js` — регистрация Service Worker, проверка обновлений и кнопка «Обновить сейчас».
- `date-utils.js` — общие функции дат, денежных сумм и единиц измерения.
- `app.js` использует эти модули через явные импорты; его размер уменьшен приблизительно с 55 до 44 КБ.
- Исправлена гонка при ручной отправке резервной копии: изменение данных, появившееся **во время отправки**, больше не помечается как уже сохранённое.
- Добавлены шесть тестов управления облачной копией; суммарно девять тестов.
- Кеш Service Worker изменён на `home-pantry-static-v050`; новые JS-модули добавлены в список офлайн-ресурсов.
- `package.json` добавлен только для удобного запуска тестов (нет новых сторонних зависимостей).

## Что намеренно не менялось

- IndexedDB `home-pantry-v1`, таблицы `products`, `events`, `shopping`, `settings` и JSON-формат резервной копии `version:1`.
- `cloud.js`, `cloud-config.js`, SQL-таблицы, функция `supabase/functions/send-expiry-push/index.ts` и схема пуш-подписок.
- Текущие настройки Supabase, VAPID, Cron, внешнее оформление и повседневные действия.

**Важно:** версия 0.5 **не добавляет синхронизацию между несколькими телефонами**. Как и раньше, обновление общего снимка выполняет основное устройство. Фоновые push продолжают использовать этот снимок.

## Как обновить через Visual Studio Code

1. В работающем приложении на телефоне открой **Настройки → Скачать JSON** и сохрани резервную копию.
2. Распакуй архив и открой папку `domashniy-sklad-v0.5`.
3. Скопируй **содержимое** этой папки поверх существующего Git-репозитория `domashniy-sklad` (в корне репозитория должен остаться `index.html`). **Не заменяй папку `.git`.**
4. **Сохрани текущий `cloud-config.js` перед копированием.** В архив включены только публичные конфигурационные значения исходной сборки 0.4.1. Если в твоём проекте более свежие значения, оставь текущий файл. Никогда не помещай сюда приватный VAPID, `CRON_SECRET`, пароли или `service_role`.
5. В терминале VS Code выполни `node --version`, затем `npm.cmd test` (в PowerShell) или `npm test` (в другом терминале). Ожидаются **9 успешных тестов**. Дополнительно `npm.cmd run check`.
6. Запусти локально `py -m http.server 8000` (или `python -m http.server 8000`) и проверь экран на `http://localhost:8000`. Не вводи реальные секреты в код. Локальное хранилище `localhost` отдельно от GitHub Pages.
7. `git add .` → `git commit -m "Рефакторинг 0.5"` → `git push origin main`.
8. Дождись успешного завершения **GitHub → Actions → pages build and deployment**. Открой установленное приложение на телефоне и нажми «Обновить сейчас», когда появится баннер. После обновления закрой и снова открой приложение.

## Проверка после публикации

- Продукты, их количество, партии, даты и месячные покупки на месте.
- Поиск и сохранение нового продукта работают, а его изменения отражаются в облачной копии основного устройства.
- В настройках Supabase по-прежнему можно войти, сохранить резервную копию и увидеть статус последней отправки.
- Web Push остаются включёнными. **Не нужно заново создавать ключи или переустанавливать push-функцию.** Если проверяешь серверный push, пользуйся уже настроенным серверным тестом.
- Кнопка обновления приложения видна при появлении следующей версии.

## Архитектура

- `app.js` — интерфейс, события и сценарии пользователя (дальнейшее разделение запланировано).
- `date-utils.js` и `inventory-utils.js` — чистые функции для дат и сортировки.
- `cloud-sync.js` и `cloud.js` — планирование резервных копий и запросы Supabase.
- `pwa-updates.js` и `sw.js` — управление обновлением и офлайн-кеш; `sw.js` также принимает push.
- `expiry-rules.js` — справочник ориентировочных сроков хранения.
- `db.js` — IndexedDB.
- `tests/` — тесты Node.js.

## Ограничения проверки

Проверены синтаксис JavaScript, доступность файлов и девять модульных тестов. Полный прогон действий на Android/iPhone и с живым Supabase после обновления нужно выполнить на своём устройстве. В случае проблемы не удаляй PWA и не очищай IndexedDB; сначала сохрани резервную копию.
