# Домашний продуктовый склад — v0.3

Рабочая PWA для GitHub Pages (Android, iPhone, компьютер). Все данные остаются в IndexedDB на текущем устройстве. Архив не содержит логинов и ключей.

## Обновить проект из v0.2 в VS Code

1. В **старом приложении**: Настройки → **Скачать JSON**; сохрани резервную копию продуктов.
2. Скачай и распакуй v0.3. Скопируй **содержимое** папки `domashniy-sklad` в текущую папку репозитория `domashniy-sklad`, заменяя совпадающие файлы. Не создавай вложенную одноимённую папку.
3. В VS Code: **Source Control → Commit** с названием `Обновление v0.3` → **Sync Changes**.
4. На GitHub открой **Actions** и дождись успешной публикации Pages. Открой сайт в браузере и убедись, что изменения появились.
5. Если установленная иконка всё ещё открывает старую версию, полностью закрой приложение и открой вновь. В дальнейшем появится предложение **«Доступно обновление → Обновить сейчас»**. После обновления v0.2 до v0.3 может потребоваться повторное открытие, поскольку старый Service Worker обновляется иначе.

Не очищай данные браузера/сайта и не удаляй установленное PWA без резервной копии: это может удалить локальные продукты. При использовании того же адреса GitHub Pages данные IndexedDB сохраняются.

## Что изменено

- **Диапазоны сроков**: расширенный справочник (`expiry-rules.js`, более 100 записей), отдельный ориентир после вскрытия; если упаковка не открыта и для продукта нет достаточного ориентира, срок не выдумывается. Для предупреждения берётся **ранняя** дата диапазона, в карточке показаны обе.
- **Количество**: ±1 шт./уп., ±100 г/мл, ±0,1 кг/л; кнопка **Использовано** списывает партию целиком, не удаляя историю покупки.
- **Быстрый ввод**: подсказки ранее сохранённых наименований, заполнение категории, места и единицы при повторном названии, **Сохранить и добавить ещё**.
- **Штрихкоды**: встроенный `BarcodeDetector` для камеры, если поддерживается браузером; иначе через интернет загружается библиотека `html5-qrcode` (unpkg); загрузка фото со считыванием штрихкода в поддерживаемых браузерах, поиск по коду в Open Food Facts. Никаких гарантий покрытия каталога. Если штатного распознавания нет, фото можно открыть отдельно в Google Lens, вручную перенести название. Полноценного распознавания продукта по внешнему виду внутри приложения пока нет.
- **Обновления**: новый Service Worker ожидает подтверждения и показывает кнопку установки свежей версии без переустановки. При публикации следующей версии **необходимо менять `CACHE`** в `sw.js` (на v4, v5 и далее), иначе установленные приложения могут не обнаружить новое содержимое. Перед полноценной автоматизацией сборки это ручная операция.
- **Уведомления**: в Настройках кнопка **«Разрешить и проверить»** запрашивает доступ и выводит тест; после разрешения при **открытии приложения** может появляться одно уведомление за день, только о продуктах со сроком сегодня или завтра. **Настоящие фоновые Web Push на закрытом приложении НЕ реализованы**. GitHub Pages не является сервером отправки; требуются учёт push-подписок, серверный планировщик и отправитель, а также доступ сервера к актуальным остаткам. Без облачной синхронизации сервер не может знать текущие остатки на телефоне. Уведомления в браузере не гарантированы при выключенном телефоне.

## Как проверить

1. Открой создание карточки, набери «Огурцы», выбери холодильник и автоматический срок: появится диапазон.
2. Поставь дату открытия на сегодня; для «Йогурта» проверь диапазон после вскрытия. Для запечатанного йогурта используй срок с упаковки.
3. Добавь запись, снова введи название: должно подставиться предыдущее место хранения и единица.
4. Сохрани и добавь ещё одну партию, затем измени количество кнопками ± и нажми «Использовано».
5. В Настройках проверь тестовое уведомление и на странице с обновлённым Service Worker увидишь баннер при следующих изменениях версии.

## Как запустить локально

Из папки проекта запусти `py -m http.server 8000` и открой `http://localhost:8000`. При необходимости проверь консоль разработчика. Для телефона используй GitHub Pages по HTTPS.

## Безопасность продуктов

Диапазоны в `expiry-rules.js` — только ориентиры для качества при надлежащей температуре и условиях хранения, не «точный срок годности» и не подтверждение безопасности. Производитель и маркировка «годен до» имеют приоритет. В сомнительных случаях не употребляй продукт; дата на упаковке и правила безопасного хранения важнее расчёта.

## Файлы

- `index.html` интерфейс и формы
- `app.js` обработчики и данные
- `expiry-rules.js` справочник ориентиров
- `sw.js` офлайн и механизм обновления
- `db.js` хранилище
- `styles.css` стили
- `cloud.js`, `cloud-config.js`, `supabase.sql` — инфраструктура **ручных** облачных копий версии 0.2, не автоматическая синхронизация.
