# Домашний продуктовый склад v0.4 — Web Push

Эта версия основана на 0.3.1. Сначала сохраните JSON-копию из предыдущего приложения. ZIP содержит **полные файлы для замены** в уже существующем репозитории GitHub Pages. Не создавайте второй вложенной папки.

## Что сделано
- Подписка телефона на Web Push в настройках; отключение на конкретном устройстве.
- При включённом облачном сохранении изменения продуктов автоматически перезаписывают единую резервную копию Supabase (после добавления, редактирования, списания, пересчёта сроков).
- Edge Function, которая каждый час определяет, где сейчас 09:00 (часовой пояс, переданный телефоном), и отправляет push о партиях, у которых `expiryMinDate` (для ориентиров) или `expiryDate` (для сроков производителя) наступает через один день или раньше, включая просроченные. Одно уведомление на устройство в сутки. Демоданные не учитываются.
- Отдельный серверный тест отправки.

**ВАЖНО:** это НЕ синхронизация нескольких телефонов! Есть одна облачная копия на аккаунт; если включить автосохранение с двух телефонов, они могут перезаписать данные друг друга. Выберите один основной телефон для изменения запасов и автосохранения; остальные пока НЕ нажимают «Сохранить в облако» и могут получать уведомления от общей копии. Для полноценного общего редактирования нужна следующая архитектура с отдельными таблицами партий и синхронизацией изменений.

## 1. Создание Supabase и таблиц
1. На https://supabase.com создайте проект, включите Auth → Providers → Email. Для первого теста подтвердите email, если включено подтверждение.
2. Dashboard → SQL Editor → New query. Выполните `supabase.sql`, затем `push-schema.sql` (запускайте каждую отдельно).
3. В Supabase → Project Settings → API Keys найдите `Project URL` и публичный `anon` или `publishable` ключ. В `cloud-config.js` заполните `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Не используйте `service_role`, `secret` или пароль базы в этом файле!

## 2. Установка Supabase CLI и ключи
В терминале VS Code (нужен установленный Node.js):

```powershell
node --version
npx supabase --version
npx supabase login
npx supabase link --project-ref ВАШ_PROJECT_REF
```

`PROJECT_REF` — часть URL до `.supabase.co`.

Генерация пары VAPID, используя команду из npm-пакета `web-push`:

```powershell
npx --yes web-push generate-vapid-keys
```

Сохраните пару ключей в безопасном месте. Публичный вставьте в `cloud-config.js` как `VAPID_PUBLIC_KEY`. **Приватный никогда не отправляйте на GitHub.** Для `VAPID_SUBJECT` используйте `mailto:ваша-почта@example.com` (замените на реальную почту).

Из корня проекта в терминале по очереди выполните (подставляя свои значения; не делитесь терминальными логами, содержащими приватный ключ):

```powershell
npx supabase secrets set VAPID_PUBLIC_KEY="ВАШ_ПУБЛИЧНЫЙ_VAPID" VAPID_PRIVATE_KEY="ВАШ_ПРИВАТНЫЙ_VAPID" VAPID_SUBJECT="mailto:ВАША_ПОЧТА"
```

Сгенерируйте длинный случайный `CRON_SECRET`. В PowerShell (не вводить значение в чат) можно выполнить:

```powershell
$bytes = [byte[]]::new(32)
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

Скопируйте результат **только** в настройки Supabase, затем:

```powershell
npx supabase secrets set CRON_SECRET="ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ"
npx supabase functions deploy send-expiry-push --no-verify-jwt
```

Не публикуйте приватный ключ и CRON_SECRET в репозитории. Edge Function получает `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` из встроенных переменных Supabase; при отсутствии проверьте настройки проекта.

## 3. Расписание в Supabase — проверка каждый час для местного 09:00
В Supabase → SQL Editor выполните **по очереди**, подставляя собственные значения:

```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;
select vault.create_secret('https://ВАШ_PROJECT_REF.supabase.co', 'pantry_project_url');
select vault.create_secret('ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ', 'pantry_cron_secret');
```

Затем:

```sql
select cron.schedule(
 'pantry-expiry-push-hourly', '0 * * * *',
 $$
 select net.http_post(
  url := (select decrypted_secret from vault.decrypted_secrets where name = 'pantry_project_url') || '/functions/v1/send-expiry-push',
  headers := jsonb_build_object(
   'Content-Type', 'application/json',
   'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'pantry_cron_secret')
  ),
  body := '{}'::jsonb
 );
 $$
);
```

Это почасовая проверка (09:00 по часовому поясу каждого подписанного устройства). Системное время cron — UTC; здесь не требуется менять час при переходе на летнее время. Cron может запускаться с задержкой, доставка push также не гарантируется ровно в 09:00.

## 4. Публикация и подключение на телефоне
1. Скопируйте содержимое архива в существующую папку VS Code. Проверьте, что `index.html` в корне репозитория. `cloud-config.js` хранит только публичные ключи.
2. Сделайте `Commit` и `Sync Changes` — GitHub Pages опубликует файлы.
3. Откройте уже установленное PWA → «Доступно обновление» → «Обновить» (при необходимости перезапустите).
4. Настройки → войдите в Supabase (если аккаунта нет — регистрация + подтверждение почты).
5. **На основном телефоне** нажмите «Сохранить в облако» — сначала это обязательно. Далее приложение будет обновлять копию после изменения запасов.
6. Нажмите **«Включить фоновые push»**, разрешите уведомления. На iPhone используйте установленное приложение через значок экрана «Домой» (iOS 16.4+).
7. Другие телефоны могут войти под тем же аккаунтом и подписаться на push, не включая автосохранение.

## 5. Проверка уведомлений (без ожидания 09:00)
В Dashboard → Edge Functions → send-expiry-push → Invoke (если доступно) или отправьте POST с JSON `{"test":true}` и заголовком `x-cron-secret: ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ`. Не раскрывайте токен. Из PowerShell:

```powershell
$headers = @{ 'x-cron-secret' = 'ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ'; 'Content-Type' = 'application/json' }
Invoke-RestMethod -Method Post -Uri 'https://ВАШ_PROJECT_REF.supabase.co/functions/v1/send-expiry-push' -Headers $headers -Body '{"test":true}'
```

Проверяйте в Edge Functions → Logs. Ответ `sent: 1` означает, что push-сервис принял одну тестовую отправку; реальное появление зависит от телефона, разрешений и сети.

Для реальной проверки создайте **не демонстрационный** продукт со сроком «завтра» в приложении на основном телефоне; убедитесь, что облачная копия обновилась, и дождитесь следующей проверки в 09:00 по поясу телефона.

## Безопасность / особенности
- Данные хранятся локально; отправка в облако возможна только после явного включения автосохранения через кнопку. Сохраняйте отдельный JSON-экспорт.
- При смене аккаунта на том же телефоне отключите push и автоматическое сохранение старого аккаунта перед выходом.
- В настройках можно выключить push на текущем устройстве.
- Рекомендательный диапазон НЕ является безопасным сроком годности. Для упаковки «годен до» приоритет у производственной даты; просроченное нельзя считать пригодным.
- Для iOS Web Push требуется установка PWA на экран «Домой», HTTPS и пользовательский жест для запроса разрешения.
- Бесплатный проект Supabase может быть приостановлен после периода неактивности; запланированные вызовы могут перестать выполняться до возобновления проекта.
